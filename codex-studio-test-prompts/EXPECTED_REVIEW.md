# Codex Studio Fictional Test Collection: Expected Review

> **For the facilitator only.** Do not show this file to the participant before they have examined the Master Codex and given their own independent response. It describes the intended ground truth and would coach the result. There is no single correct wording for the generated Master Codex.

## Purpose

These files provide a safe, fictional prompt collection for the first Codex Studio session. They contain no private, client, financial, medical, or production information.

The collection deliberately includes repetition, dependencies, future-stage ideas, and conflicts. It tests whether the resulting Master Codex makes those relationships understandable without silently losing instructions.

Codex Studio's task in this test is only to organize these written instructions into a Master Codex. It is not asked to build Encore Notes, run any command, access private information, or contact any external service. Encore Notes is imaginary; the instructions are only material to organize.

## What a Careful Result Should Preserve

- The product is called Encore Notes.
- It helps working bandleaders prepare shows.
- Its first useful result is a clear set list.
- The visible language should be familiar to musicians.
- The five first-release actions should remain present.
- Feedback should come after the first successful set-list export.
- Financial support is optional, later, and value-first.

## Deliberate Repetition

“Use plain, welcoming language” appears in more than one file. A useful Master Codex may combine the repetition, but it should not lose the requirement.

## Deliberate Conflicts

The final file conflicts with earlier instructions about:

- Guest access versus registration before viewing anything.
- Familiar musician language versus technical labels.
- Feedback and support after value versus an immediate donation request.
- No popularity design versus public follower rankings.
- Deferred payment work versus building payments before validation.

A useful result should identify these conflicts or present them clearly for a human decision. It should not silently treat the later file as automatically correct.

## Ordering Dependencies

A useful order would establish:

1. Purpose and intended person.
2. Public language.
3. First-release experience.
4. Feedback after the meaningful result.
5. Possible future support.
6. Conflicts requiring a creator decision.

The exact wording may differ. The test is whether the participant can understand what belongs now, what belongs later, and what requires a decision.

## Important Limitation

This expected review must not be shown to the participant until after they have examined the Master Codex and given their independent response. Otherwise it would coach the result.
