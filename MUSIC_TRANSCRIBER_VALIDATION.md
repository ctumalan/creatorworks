# CreatorWorks Phase 0: Music Transcriber

## Session Status

**Planned subsequent validation — waiting for a working web-accessible experience**

Music Transcriber is a planned *later* Phase 0 validation case, not the first. The first real Phase 0 session uses Codex Studio (see [CODEX_STUDIO_VALIDATION.md](CODEX_STUDIO_VALIDATION.md)). This Music Transcriber session should be scheduled only once the work has a working, web-accessible experience that a participant can reach without the creator guiding every step.

When it runs, it will be a **manual CreatorWorks Experience Session** in the **guided-external-link** mode (see the four experience modes in the product plan). It could move to a **connected application** later, once a CreatorWorks Connection Kit exists. The goal is not only to learn whether Music Transcriber is useful, but whether Gilberto can receive the invitation, understand the work, reach it, try it, open the result in Sibelius, and return with feedback **without the creator guiding him through every step.**

Two things still need to be confirmed before inviting Gilberto:

- **How Gilberto will reach Music Transcriber.** This document does not assume the work is used on the web or as a download. A web-accessible experience is what would let this session run cleanly as a guided external link. The access method is an open decision that must be resolved first (see "Access and Trust Decisions to Resolve Before the Session").
- **The test score.** A representative printed jazz score must be chosen (see "Recommended First Test").

## The Sharing Handoff Being Tested

Music Transcriber will test the sharing loop from the product plan, run as a manual CreatorWorks Experience Session:

> **Present → Share → Experience → Respond → Recognize**

On his own, Gilberto should be able to:

- Receive the invitation and understand what Music Transcriber is.
- Understand why it may matter to him and who made it.
- Recognize that it is an early version that works best with jazz-oriented music.
- Reach and access Music Transcriber, following any installation steps himself.
- Try it with an appropriate jazz score.
- Open the resulting MusicXML file in Sibelius.
- Understand what the creator wants him to notice.
- Return to the CreatorWorks feedback experience and respond.

The creator should step in only if Gilberto becomes truly stuck—and every such moment should be recorded, because it shows where the handoff needs to improve.

## The Work

**Music Transcriber** turns printed sheet music or handwritten scores into an editable MusicXML file that can be opened and edited in Sibelius.

Its intended benefit is simple:

> Spend less time copying music note by note and more time composing, arranging, producing, and preparing the performance.

## Who It May Help

- Composers
- Producers
- Music copyists
- Arrangers
- Band leaders

## What Someone Can Experience Today

The current version works best with jazz-oriented sheet music. A person can give it a score, receive a MusicXML result, open that result in Sibelius, and compare it with the original music.

## What Is Still Unfinished

The current version is not yet equally reliable with:

- Complex classical scores
- Orchestral scores
- Atonal music
- Contemporary notation
- Other unusually dense or specialized written music

This limitation should be stated before the invitation so the first session tests the work honestly.

## First Person to Invite

**Gilberto — producer and trusted friend**

Gilberto is a relevant first person because he understands musical notation and the time involved in preparing editable music.

## One Main Question

> After using Music Transcriber on this jazz score and opening the MusicXML file in Sibelius, was the result accurate enough to save meaningful time compared with entering the music manually?

This is more useful than asking only whether it “worked.” It tests both technical accuracy and the human benefit that matters: saved time.

## What to Notice

These observations support the one main question. They are not separate tests Gilberto must pass.

- Did the MusicXML file open successfully in Sibelius?
- Were the pitches and rhythms mostly correct?
- Were measures, rests, voices, chords, and other important markings preserved well enough to continue editing?
- What required manual correction?
- Was correcting the result faster than entering the score from the beginning?
- Would Gilberto choose Music Transcriber again for a similar score?

## Recommended First Test

Begin with one representative **printed jazz score** that the creator owns or has permission to use.

Printed music is recommended for the first session because it removes handwriting quality as an extra source of uncertainty. A later session can test a handwritten jazz score separately.

The score should be:

- Long enough for time savings to matter
- Short enough to compare carefully during one session
- Typical of the jazz material Music Transcriber currently handles well
- Legally available for this test
- Free of private information that should not be uploaded

## Session Flow

Let Gilberto move through this on his own wherever possible. Watch quietly, and only help if he becomes truly stuck—then note where that happened.

1. Send Gilberto the invitation the way a real recipient would receive it (a link, a QR code, or a message).
2. Let him read the invitation and the honest description of the early version, and say in his own words what the work is and why he was invited.
3. Confirm beforehand what will happen to the score he provides and whether it will be stored, so he knows before he starts.
4. Let Gilberto reach and access Music Transcriber himself, following any installation or access steps.
5. Give Music Transcriber the selected printed jazz score.
6. Let the transcription finish without coaching unless Gilberto becomes blocked.
7. Save the MusicXML result.
8. Open the MusicXML file in Sibelius.
9. Compare the result with the original score.
10. Have Gilberto return to the CreatorWorks feedback experience on his own to respond.
11. Ask the one main question.
12. Record where the result saved time and where it created correction work.
13. Note every point where the creator had to step in for the handoff to continue.
14. Thank Gilberto and explain what was learned, decided, or changed afterward.

## Warm Invitation Draft

> Gilberto, I am trying an early version of Music Transcriber. It turns a printed score into a MusicXML file that can be opened in Sibelius.
>
> It currently works best with jazz-oriented music and is not yet ready for every kind of complex score. I would value your honest experience with one jazz score.
>
> The main thing I want to learn is whether the result is accurate enough to save meaningful time compared with entering the music manually. You are not being asked to praise it—becoming stuck or finding incorrect notes would be useful for me to understand.

## Feedback Prompt for Gilberto

> After opening the result in Sibelius, did Music Transcriber save you meaningful time compared with entering the score manually? Please tell me what transferred well, what needed correction, and whether you would use it again for a similar score.

## Creator Follow-Up

After reviewing Gilberto's experience, record:

- What worked better than expected
- What caused the most correction work
- What was learned
- What will be changed or tested next
- Why any suggested change will not be pursued
- Whether Gilberto wants his contribution kept private or recognized later

Then send Gilberto a short update so he can see that his time mattered.

## Support Learning — Not a Payment Feature

Do not charge Gilberto, ask for any payment details, or build payment functionality during this session. Payment is never an entrance requirement, and no support prompt should do anything real. Any support idea shown here is a nonfunctional concept used only for learning.

The point is not to decide a price. It is to learn whether a simple thank-you would feel natural **after** Gilberto has already experienced the value—an idea the product plan calls value-first support.

Only after the usefulness test is complete, ask:

> If Music Transcriber saved you meaningful time, would you want a simple way to support its creator afterward? What would make that invitation feel natural and appreciative rather than pressured?

If it helps the conversation, you may ask, as a secondary question, what kind of financial relationship he would eventually expect—for example an optional tip, a one-time thank-you, or ongoing support. Keep this secondary, and keep it clearly separate from the experience itself.

Use words like "support," "tip," or "optional thank-you." Do not describe this as a charitable donation.

This records a future business-model signal without mixing payment pressure into the first experience.

## Access and Trust Decisions to Resolve Before the Session

This document does not assume that Music Transcriber is used on the web or as a download. That is an open decision, and the session cannot be scheduled until it and the items below are settled. Getting these right is what lets Gilberto reach and experience the work on his own.

Before sending the invitation, confirm:

- **Web or downloadable access.** Will Gilberto use Music Transcriber on the web, or download and run it? This must be decided, not assumed.
- **Device and operating-system requirements.** Which computer, operating system, and versions are needed?
- **Whether registration is required.** Does Gilberto need to create any account or sign in?
- **Installation steps.** If it is a download, what exactly must he install, and in what order?
- **Whether files are uploaded or stored.** Will the score he provides be uploaded, where does it go, is it stored, for how long, who can view it, and can it be deleted?
- **Privacy and artificial-intelligence disclosures.** What data is collected, and does the work use artificial intelligence in a way that affects his expectations, rights, privacy, or safety? State this plainly before he starts.
- **A tested return path to the CreatorWorks feedback experience.** Confirm, by trying it yourself first, that after using the work Gilberto has a clear, working way back to leave feedback.

Also confirm the practical details that keep the test honest:

- Which Sibelius version will be used.
- What Gilberto should do if the file does not open or the process fails.
- That no personal or payment information is requested during the session.

Write down the answers before inviting Gilberto, so the invitation and project page can state them honestly.

## Provisional Success Signs

The first session provides promising evidence if:

- Gilberto understood the work from the invitation and reached, accessed, and tried it largely on his own.
- The MusicXML result opens in Sibelius.
- Gilberto can continue from the result instead of starting the transcription again.
- Correcting the result takes meaningfully less time than manual entry.
- The largest errors can be described clearly enough to guide improvement.
- Gilberto would consider using Music Transcriber again for similar jazz material.
- Gilberto feels that the invitation, test, and follow-up respected his time.

A poor transcription is still useful Phase 0 evidence if the experience makes the limitation clear and produces a specific next decision.
